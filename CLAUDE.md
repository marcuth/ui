# CLAUDE.md

TypeScript package `@marcuth/ui`: Next.js + React 19 + Tailwind v4 design system built on shadcn/ui, with a per-site configurable theme.

## Commands

- `npm run dev`: runs the Next.js playground (`playground/`), which compiles the library from `src/`.
- `npm run build`: `tsc -p tsconfig.build.json` file by file, `tsc-alias` (resolves `@/` and adds `.js`), then copies `src/*.css` to `dist/`.
- `npm run typecheck`: type-checks the library/tests and the playground.
- `npm run lint`: runs ESLint.
- `npm run lint:fix`: runs ESLint with auto-fix.
- `npm run format`: formats the code with Prettier.
- `npm run test`: runs the tests with Vitest (jsdom).
- `npm run test:cov`: generates the coverage report.
- `npm run icons`: regenerates `src/icons/*.ts` from react-icons' manifest (run after upgrading react-icons).

## Structure

- `src/index.ts`: public entrypoint (barrel).
- `src/tokens.css`: plain-CSS tokens (identity + knobs). `src/theme.css`: Tailwind entry (`@theme inline`, `@source "./"`, `dark` variant). Both stay at the `src` root so `@source "./"` works in `src` and in `dist`.
- `src/components/ui/`: shadcn/ui components (CLI-generated, adapted to the tokens) + `link.tsx` (`Link`/`Anchor`).
- `src/components/`: library compositions (`AppHeader`, `AppFooter`, `BrandMark`, layout, typography, `theme/ThemeToggle`).
- `src/theme/`: `defineTheme`/`applyTheme`, contrast helpers, theme mode cookie, `ThemeScript`.
- `src/icons/`: one entry point per react-icons set (`@marcuth/ui/icons/<slug>`), exported via `./icons/*` in package.json. Generated by `npm run icons` (`scripts/generate-icons.mjs`, slug map + react-icons manifest); don't edit them by hand. `index.ts` holds the shared primitives.
- `src/lib/utils.ts`: `cn` (`clsx` + `tailwind-merge` extended with the theme scales). `src/lib/href.ts`: internal/external href detection.
- `__tests__/`: unit tests (Vitest + Testing Library).
- `playground/`: Next.js app, not published. `tsconfig` paths point `@marcuth/ui` and `@/*` at `../src`.

## Conventions

- Run `npm run lint:fix` and `npm run test` before finishing a change.
- Unused variables and arguments must be prefixed with `_`.
- Commit messages follow Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`).
- **shadcn/ui first**: add base components with `npx shadcn@latest add <name>`; never hand-write one shadcn already has. The CLI writes `import { cn } from "cn"` and skips `radix-ui`: after adding, run `sed -i 's#from "cn"#from "@/lib/utils"#' src/components/ui/*.tsx`, uninstall `cn` if it was added, and make sure `radix-ui` is a dependency.
- When adapting a shadcn component, only touch theme hooks: single-line controls use `rounded-control` and `h-control-*`; multi-line/surfaces keep the bounded shadcn scale (`rounded-lg`, `rounded-xl`) so `pill` never over-rounds them. Add variants (e.g. `brand`) rather than changing existing ones.
- **Links**: internal hrefs must go through Next.js `<Link>`. Use `Link` (styled) or `Anchor` (unstyled, for `Button asChild`); never a raw `<a>` for internal routes.
- Naming: app-shell pieces are `App*` (`AppHeader`, `AppFooter`), not `Site*`.
- Imports use the `@/` alias inside `src`; no file extensions.
- Components are server-safe by default. Only files that need hooks/DOM declare `"use client"` (`tsc` keeps the directive per file; do not bundle).
- Color tokens use shadcn names; every other token is prefixed `--ui-` to avoid colliding with Tailwind's theme namespaces. When adding a token: declare it in `tokens.css` (both theme blocks if derived), map it in `theme.css`, and register new scales in `src/lib/utils.ts`.
- Identity comes from marcuth.dev: zinc neutrals (exact shadcn values), emerald-500 `#00bc7d` brand with white ink, Geist, pill controls, dark default. Don't drift from it without checking the portfolio.
- Brand wordmark is `{name}.marcuth.dev` (`BrandMark`, `brandName`).
- Icons: Lucide (`react-icons/lu`) for UI; never hand-draw SVGs that exist there.
- Motion (Emil Kowalski rules): transition exact properties (Tailwind v4 `scale-*`/`translate-*`/`rotate-*` are their own CSS properties, list those, not `transform`), use `ease-out` (mapped to the strong curve) and `--ui-duration-*`, never `transition-all`, never animate from `scale(0)`, no motion on hover-only/keyboard interactions, always a `motion-reduce:` path that keeps fades and drops movement.
- A component enters the library once it has a real use in two sites.
